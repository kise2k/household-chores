# Backlog: Household Chores

Этот backlog составлен на основе [`_docs/plan.md`](_docs/plan.md). Задачи расположены в порядке реализации и рассчитаны на небольшую первую версию приложения.

## Task 1. Создать модели данных и миграции

**Статус:** выполнено.

Создать основу приложения в `chores/models.py`:

- `FamilyMember` — участник семьи с именем;
- `ChoreSchedule` — описание дела, ответственный, тип повторения (`one-time`, `daily`, `weekly`), ближайшие дата и время выполнения и признак активности;
- `ChoreOccurrence` — отдельное выполнение дела с дедлайном и временем фактического выполнения.

Добавить модели в Django Admin, создать и применить миграции.

**Критерии готовности:**

- участника семьи можно сохранить с непустым именем;
- дело обязательно связано с участником;
- поддерживаются разовые, ежедневные и еженедельные расписания;
- отдельный экземпляр дела хранит дедлайн и состояние выполнения;
- модели доступны в Django Admin;
- `uv run python manage.py check` выполняется без ошибок.

## Task 2. Добавить управление участниками семьи

**Статус:** выполнено.

Создать страницы общего доступа без авторизации:

- список участников;
- форма добавления участника по имени;
- удаление участника, если с ним не связаны дела.

Добавить навигацию, понятные сообщения об ошибках и базовые шаблоны страниц.

**Критерии готовности:** участника можно добавить через браузер, он появляется в списке и доступен при назначении дела.

## Task 3. Добавить создание разовых и повторяющихся дел

**Статус:** выполнено.

Создать форму нового дела с полями:

- название;
- ответственный;
- дата и время первого выполнения;
- тип повторения: без повтора, ежедневно или еженедельно.

При сохранении создавать расписание и первый отдельный экземпляр дела.

**Критерии готовности:** корректное дело сохраняется, а незаполненные или противоречивые данные показывают ошибки формы.

## Task 4. Реализовать общий список дел и отметку выполнения

**Статус:** выполнено.

Показать все экземпляры дел в общем списке, отсортированном по сроку. Для каждого дела отображать название, ответственного, дедлайн и состояние.

Добавить действия:

- отметить дело выполненным;
- отличать выполненные, предстоящие и просроченные дела;
- отфильтровать список по ответственному и состоянию.

**Критерии готовности:** просроченным считается невыполненное дело с дедлайном в прошлом; каждое дело можно отметить выполненным отдельно.

## Task 5. Генерировать повторы и покрыть приложение тестами

**Статус:** выполнено.

Добавить команду Django для создания наступивших экземпляров ежедневных и еженедельных дел. Новый экземпляр должен создаваться независимо от состояния предыдущего, а повторный запуск команды не должен создавать дубликаты.

Покрыть тестами основные сценарии:

- создание участника и дела;
- валидация формы;
- определение просроченного дела;
- отметка выполнения;
- ежедневное и еженедельное повторение;
- сохранение невыполненного предыдущего дела;
- защита от дублирования повторов.

Обновить README с итоговыми командами запуска приложения, генерации повторов и тестов.

**Критерии готовности:** `uv run python manage.py test` и `uv run python manage.py check` выполняются без ошибок.
